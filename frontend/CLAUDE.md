# Frontend: CLAUDE.md

Vite + React 19 + TypeScript (strict) for Querylab. Static build, served from
Cloudflare on the same domain as the API in production.

## Commands

| Task                                               | Command                              |
| -------------------------------------------------- | ------------------------------------ |
| Dev server (in Docker, with the rest of the stack) | `make dev` from the repo root        |
| Tests (Vitest + React Testing Library)             | `pnpm test` / `pnpm test:watch`      |
| Lint (ESLint, type-aware)                          | `pnpm lint`                          |
| Types                                              | `pnpm typecheck`                     |
| API types from `backend/openapi.json`              | `pnpm gen:api` (CI: `gen:api:check`) |
| Format                                             | `pnpm format` / `pnpm format:check`  |
| Production build                                   | `pnpm build`                         |

## Layout

```
env.config.ts        dev-server env schema (DEV_SERVER_PORT, API_PROXY_TARGET) + proxied paths
env.test.ts          .env.example must list exactly the keys the code reads
vite.config.ts       React, Tailwind, @ alias, dev proxy (/api, /_allauth, /accounts -> Django)
vitest.config.ts     jsdom tests (no dev-server env needed)
components.json      shadcn/ui config (`pnpm dlx shadcn add <name>` adds a component)
src/
  env.ts             Zod schema for import.meta.env; parseEnv()
  EnvErrorScreen.tsx shown instead of the app when env is invalid
  main.tsx           boot: env -> api + query client -> /api/me -> router -> render (see FLOW.md)
  boot.ts            ends the boot screen (timing) or shows its failure state
  router.tsx         createAppRouter(queryClient); RouterContext
  routes/            TanStack Router file routes: __root, _public/*, _app/*, _site/* (Privacy, Terms; no guard), design (dev only)
  routeTree.gen.ts   generated by the router plugin (committed; never edit)
  lib/api/           the API client (envelope, ApiError, CSRF, 429 toast, getPage, openStream, no retries)
  lib/api/schema.gen.ts  types generated from backend/openapi.json (never edit; `Schema<'Name'>` in types.ts)
  lib/api/errors.ts  user wording for every API error code (checked against backend/API_ERRORS.md)
  lib/api/error-text.ts, form-errors.ts  turn an ApiError into text / field errors
  lib/query-client.ts  TanStack Query defaults (no retries, no refetch on focus/reconnect)
  features/<name>/   per-feature queries (api.ts) and components: auth, health, limits, schema, ask,
                     history, workspaces (list, import a dump, read-only query), llm-keys, workbench, design,
                     landing (landing sections, legal pages, navbar, footer)
  components/QueryBoundary.tsx  a component's loading / error / empty / success
  styles/boot.css    the boot screen (linked from index.html)
  styles/tokens.css  every design token (light + dark); the only place colours are defined
  index.css          Tailwind, fonts, tokens -> Tailwind theme (@theme inline), base styles
  lib/utils.ts       cn() for class names (tailwind-merge taught our type scale)
  components/ui/     base components (button, input, form, dialog, table, ...) - features import from here
  components/typography/  Heading, Text, Code, CodeBlock
  stores/theme.ts    theme preference (Zustand, persisted); index.html applies it before first paint
  features/design/   DEV-ONLY /design showcase (every token and component, light and dark)
  test/setup.ts      jest-dom matchers, stubs for matchMedia, ResizeObserver, Element.animate
build.test.ts        a production build must not contain the /design page
docs/design-system.md   the design system (final); change it together with tokens.css and /design
```

Route groups are pathless layouts: `_public` (the plan's "(public)") and `_app`
("(app)"); the underscore keeps them out of the URL.

## Conventions and rules

- **Always use the impeccable skill when editing the frontend** (invoke `impeccable` before any UI change: new screens, component edits, styling, copy). Its detector (`impeccable detect --json src index.html`) must report nothing before a commit. The design system in this repo stays the source of truth where the two differ.
- `main` is protected; work happens on branches; Conventional Commits. Claude commits locally only; Aadarsha reviews and pushes.
- **No fallback env values.** Every variable is required and validated with Zod (`src/env.ts`, `env.config.ts`). A new variable goes into the schema and `.env.example` together; `env.test.ts` fails otherwise.
- **No magic numbers.** Timeouts, limits and sizes go into `.env` (and the schema), never inline.
- **State rule:** server data (user, health, later runs) lives in TanStack Query; UI-only state (theme, sidebar, modals) lives in Zustand. Never copy server data into Zustand.
- **Route guard rule:** guards run in the layouts' `beforeLoad` (`_public.tsx`, `_app.tsx`) using the cached `meQuery`: signed in on a public route -> `/ask`; signed out on an app route -> `/`. `_site.tsx` (`/privacy`, `/terms`) has no guard on purpose: both must open signed in and signed out.
- **Privacy and Terms describe the code.** When what is collected, stored or sent to an LLM provider changes, change `features/landing/PrivacyPage.tsx` and `LEGAL_LAST_UPDATED` in the same commit. The landing page's eval numbers come from `backend/DECISION.md` and its limits (50 MB, 3 workspaces) from `backend/.env.example`; they are static copy, so update them by hand.
- **Fetching data:** define a `queryOptions` in `features/<name>/api.ts` using `api` from `@/lib/api`, call `useQuery` in the component that shows it, and render through `<QueryBoundary>`. Never fetch in a route loader for component data, and never add `retry`.
- **Use the design system, never ad-hoc styles.** Colours, spacing, radius, shadows and motion come from tokens; components come from `src/components/ui/`. No raw hex values or one-off pixel sizes in feature code.
- Icons: Hugeicons only, always through `<Icon icon={...} size="sm|md|lg" />` from `components/ui/icon` (16/20/24 px, nothing else).
- **Every button has an icon:** `<Button icon={PlayIcon}>Run query</Button>`; icon-only buttons use `size="icon"`/`"icon-sm"` and must have `aria-label`. TypeScript enforces both; don't work around it.
- **Data states (design-system.md §13):** every component that fetches owns its loading (skeleton), error (`ErrorState` with a Try again that refetches only its own data), empty (`EmptyState`) and success states, inside its own box and at the same size. Never a page-level spinner or error for component data. No automatic retries and no refetch on focus/reconnect, anywhere.
- **Boot screen (§14):** the only global loading state, first page load only; the only full-page error is "can't reach the server" at boot.
- Toasts: render `<Toaster />` once; call `toast` from `components/ui/toast-api`.
- Design showcase: `pnpm dev`, then open `/design` (dev only; `build.test.ts` checks it never ships).
- Package manager: **pnpm** only (`packageManager` in package.json; `pnpm-lock.yaml` is the lockfile). Never run npm or yarn here: mixing them breaks node_modules.
- UI components are plain shadcn/ui (Radix + Tailwind), adapted to our tokens. **Select is the shadcn base-nova one (Base UI, `@base-ui/react`)**, ported with Hugeicons: keep its look when changing fields (input, select and textarea share the `rounded-lg` radius, `border-input` and the surface fill). `<Select>` passes the string value to `onValueChange` and builds its `items` from the `<SelectItem>` children, so the trigger shows labels. After `shadcn add`, replace its Lucide icons with `<Icon>` (Hugeicons), import `cn` from `@/lib/utils`, and keep the variant names used on `/design`. Animations come from `tw-animate-css` with our `duration-*` tokens.
- Don't skip or disable failing tests; fix the cause.
- **Contract first.** Types come from `backend/openapi.json` through `Schema<'Name'>`; never hand-write a response type. When the backend changes, run `pnpm gen:api`. Two API schemas with one class name collapse into one in `openapi.json` (a backend test guards this).
- **No retries, no polling, no timers, no `EventSource`** (owner's rule, enforced by `no-retry.test.ts`). The user reloads, presses a component's Try again, or presses Reconnect on the live run.
- **Errors are shown by code**, not by message: `describeError(code)` and `errorText(error)`; field errors go next to their field (`applyApiErrors`).
- **The workspace is in the URL** (`?workspace=`), never in Zustand, and part of every query key that depends on it.
- **Staff screens** are guarded by `me.is_staff` in `workbench.tsx` and hidden from the nav; the API is the real check.
- Every screen has tests with a mocked server (`serveApi` in `src/test/http.ts`); `states.test.tsx` checks the loading and error box of every data screen and `a11y.test.tsx` runs axe on every screen.
